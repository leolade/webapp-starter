# PWA

Works with or without a backend. Generated by assets (not by `ng add @angular/pwa`, which would also edit
`app.config.ts` and fetch Angular-branded icons): `manifest.webmanifest`, `ngsw-config.json`, placeholder icons
(`scripts/make-pwa-icons.mjs`: neutral dark square and white disc, 192, 512 and maskable 512), `index.html` with the
manifest link and theme colour, `serviceWorker: "ngsw-config.json"` in the production build configuration,
`provideServiceWorker` in `app.config.ts`, `@angular/service-worker`, an `UpdateBanner` component, a Playwright `pwa`
project, and `.claude/rules/pwa.md`.

## Behaviour to know

- The service worker only runs in production builds (`enabled: !isDevMode()`); `ng serve` never has one. e2e therefore
  builds first and serves `dist/` on port 4300 with `e2e/serve-dist.mjs` (a tiny static server with SPA fallback, no extra
  dependency).
- Registration is `registerWhenStable:30000`: after the app is stable or 30 s, whichever first.
- `navigationUrls` excludes `/api/**` so API calls are never answered with `index.html`. Do not cache API responses
  unless a `dataGroups` entry is added on purpose.
- Updates: new versions download in the background; `UpdateBanner` offers a reload. Hashed assets are immutable;
  `index.html`, `ngsw.json`, `ngsw-worker.js` and the manifest are served `no-cache` by the generated nginx config.
- Installability: manifest with name, `display: standalone`, 192 and 512 icons, HTTPS in production.

## Before shipping

Replace the placeholder icons and theme colour with real brand assets (keep the file names or update the manifest and
the e2e expectations), set a real `name`/`short_name`, and decide the offline story explicitly: the default only caches the
app shell and static assets. An offline-capable feature needs `dataGroups`, an offline-first UX and an e2e test using
`context.setOffline(true)`.
